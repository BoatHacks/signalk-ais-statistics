## Approach
**Settings, two tiers.** Basic settings stay in the server's config form
(`configSchema` in `src/config.ts`). Review each default (publish interval,
retention, H3 resolution, cap percentile, events) and order the form with a
`uiSchema` `ui:order` and clearer titles. Keys stay flat: nesting them into
groups would change the stored shape of existing configs. Effective
settings, already in `/status` as `config`, get a read-only panel in the web
app.

**Live settings.** `config.ts` exports a `LIVE_SETTINGS` list of option keys
that the web app may change and save. In this issue it holds
`coverageDistancePercentile` (a slider on the map, 50 to 100). The #13
alert factor, vessel count and sustained minutes join the same list when
#13 lands (maintainer, after review). The #17 drift thresholds and all
other options stay in the server config form. Changing a control changes the view at once through a read-only
query parameter (`GET /coverage?cap=95`, validated like the config, part of
the cache key); nothing is stored until the user presses save. The overlay
keeps using the saved value.

**First write route.** `POST /settings`, registered with
`router.access('readwrite').post`; on servers without `access()` it falls
back to admin-only by registering on the router directly. It accepts JSON
with only `LIVE_SETTINGS` keys (400 for any other key or a wrong type, 415
unless `Content-Type` is `application/json`, so a plain HTML form cannot
post to it), merges them into `app.readPluginOptions().configuration`,
passes the result through `resolveConfig`, saves with
`app.savePluginOptions(configuration, cb)`, applies the values to the
running state (for example a `Coverage.setPercentile`), clears the route
caches and answers with the effective settings. SPEC 6.1 and ARCHITECTURE 6
change in the same PR: one write route, readwrite, only for live settings.

Verified in the published packages (`@signalk/server-api` 2.35.0 typings,
`signalk-server` 2.35.1 `dist`), not on a running server:
- `savePluginOptions(configuration, cb)` and `readPluginOptions()` exist.
  The server writes `{ ...storedOptions, configuration }` atomically, so it
  replaces the whole `configuration` object: the route must merge first.
  It does not restart the plugin (only the admin `/config` route does), so
  the plugin applies the change itself.
- `router.access('readwrite')` offers `post`, and the server's write
  middleware lets `admin` and `readwrite` principals through, everyone when
  security is off. The server parses JSON bodies globally (`bodyParser.json`).
- `GET /skServer/loginStatus` returns `status`, `authenticationRequired`
  and, when logged in, `userLevel` (`readonly`, `readwrite` or `admin`).
  Without security it returns `authenticationRequired: false` and no
  `userLevel`. It is rate limited, so the app reads it once per load. The
  save button shows when security is off or `userLevel` is `readwrite` or
  `admin`; a 401 or 403 from the POST still hides it and explains why.

Checked on the development server (findings.md, 2026-11-01): the admin
config form shows the saved value after a POST, and a later save from that
form keeps it. Refused users get the server's 401 before the route runs.

**README.** Outline: what it does; requirements; install from the App
Store; first run and what each view shows (overview, charts, sectors, map,
with screenshots); live settings and who can save them; configuration table
generated by hand from `configSchema`; history provider setup (path filter
`sensors.ais.statistics.*`, about 14 days retention); Freeboard-SK overlay
(3.4.0 or later, reload after updates); troubleshooting (double counting
from two events, no own position, blank server charts, live-only mode,
"please log in"); published paths (link to `docs/paths.md`, no promise);
development; license. Screenshots come only from `scripts/screenshots.cjs`
(MID 999 MMSIs around 0N 0E); add one of the map with the cap slider.

**`docs/paths.md`.** One row per path pattern (`distance.bin.<nn>`,
`sectors.<nnn>.<class>.count`, ...) with unit, kind (counter or gauge) and
cadence (publish interval or hourly), plus a note that names may still
change before user feedback settles them.

**SPEC 13.1.** The maintainer opens the overlay in Freeboard-SK 3.4.0 or
later on the development server, once with a few days of traffic and once
with synthetic day files of a few thousand cells copied into the plugin
data directory, and notes pan and zoom smoothness. Only counts and sizes go
into findings.md and SPEC 6.3; 13.1 is then removed.

## Test Strategy
All unit tests, with the in-process fakes in `test/fixtures/` and synthetic
MID 999 data. Gaps found in `test/`:
- `histogram.test.ts`: no merge test (`addInto` of split histograms equals
  one pass), no percentile monotonicity in p, no bin edge cases at exact
  edges or 512 nm. Add property style tests with a seeded generator in the
  test file (no new dependency, the registry harness runs offline).
- `query.test.ts`: the 20 report sectors minimum has no 19 versus 20
  boundary case; no check that live and history derived avg and p99 agree.
- `history.test.ts`: resets are covered; add several restarts in one
  window and a reset at the first bucket.
- `coverage.test.ts`: no test that 100 disables the cap, of a cap from a
  merged multi-day histogram, or of a changed percentile.
- `longrange.test.ts`: the 50 per day limit is covered; add the 40
  character name cut and per MMSI replacement by a farther report.
- `paths-doc.test.ts` (new): every pattern from `paths` appears in
  `docs/paths.md` and every documented pattern exists; units match
  `defaultMetadata()`; hourly cadence matches `buildValues({ sectors })`.
- `api.test.ts`: `POST /settings` is registered readwrite (admin-only
  without `access()`), rejects unknown keys, bad types and non-JSON, merges
  instead of replacing, applies live and clears the cache; `cap` parameter.
- `config.test.ts`: every `LIVE_SETTINGS` key has schema bounds that match
  `resolveConfig`.
- Coverage report: `@vitest/coverage-v8` is not installed. Add it as a dev
  dependency with a `test:coverage` script, run once, fill the gaps found.
- Web: `test/web/` gains a pure `canSave(loginStatus)` test. Manual: phone
  width, offline, save shown and hidden for each user level.
